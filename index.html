Decisions

Engineering judgment

Real situations. Real trade-offs. The decisions that shaped production systems.

Engineering decision

Node.js → .NET Core: Full Rebuild vs. Incremental Refactor

Situation: The MyAlgoAI trading backend had deeply coupled monolithic structure in Node.js — 10-second API responses, no multi-threading, and pervasive coupling between business logic and infrastructure. The question was how to fix it.

Option A

Incremental Node.js refactor — lower risk, gradual improvement, avoids big-bang rewrite. Tech debt addressed layer by layer.

Option B

Chosen

Full rebuild in .NET Core Clean Architecture — proper domain/application/infrastructure separation from the ground up, enabling safe multi-threading and caching.

Rationale: The monolithic coupling meant any incremental refactor would carry the structural debt forward. Multi-threaded order execution is only safe when domain logic is cleanly separated from infrastructure — something impossible to retrofit without a structural break.

Trade-off: Full rebuild carries rewrite risk and requires feature parity validation. Mitigated by phased rollout with the existing Node.js backend as a live fallback during transition.

Result: 10× throughput improvement. API response from 10s → 300ms. Platform now handles 500+ concurrent users across 4 brokers.

Engineering decision

XSLT Transformation vs. C# Code Mapping for ByBar Pipeline

Situation: ByBar's product records required complex structural transformation from source schema to a Canonical Data Model. 10–20 million records per sync. Two approaches: declarative XSLT or imperative C# mapping code.

Option A

C# code-based mapping — explicit control, unit-testable field by field, familiar language. Schema changes require code changes and redeployment.

Option B

Chosen

XSLT transformation — declarative, schema-portable, natively integrated in Azure Logic Apps. Schema changes are XSLT updates, not service redeployments.

Rationale: XSLT integrates natively with Azure Logic Apps at no additional runtime cost. Keeping transformation declarative and outside application code means the transformation layer can be updated independently — critical for an enterprise client where product schema evolves.

Trade-off: XSLT is less familiar than C# and harder to debug. Requires XPath proficiency and specialist tooling for development.

Result: Transformation pipeline processes 10–20M records within the 4-second SLA. Schema updates deployed without backend service changes or downtime.

Engineering decision

Bicep IaC vs. Manual Azure Portal Configuration

Situation: ByBar integration uses 5 Azure services across multiple environments. Manual portal configuration is fast for prototyping but creates environment drift — staging and production diverge silently.

Option A

Azure Portal configuration — faster initial setup, no Bicep authoring overhead. Acceptable for single-environment proof-of-concept.

Option B

Chosen

Azure Bicep IaC — all services version-controlled, deployable to any environment from a single pipeline run, auditable and repeatable.

Rationale: An EU enterprise client requires production-grade, auditable, repeatable deployment. Manual configuration is a maintenance liability — impossible to audit, impossible to reproduce exactly across environments, and unacceptable under enterprise SLAs.

Trade-off: Bicep adds authoring time and requires understanding ARM template structure. This upfront cost is repaid on the first multi-environment deployment.

Result: Full integration stack deployable from a single Bicep + YAML pipeline run. Zero environment drift. Staging mirrors production exactly.

Principles

How I think

Engineering values shaped by real production experience.

ARCHITECTURE FIRST

Structural problems cannot be solved by adding features. Fix the architecture or carry the debt forever.

MyAlgoAI: Node.js → .NET Core Clean Architecture rebuild. Incremental refactor was not an option — monolithic coupling made multi-threading unsafe. Result: 10× throughput.

IAC OR IT DIDN'T HAPPEN

Infrastructure defined outside version control is infrastructure you cannot trust, reproduce, or audit.

ByBar: entire Azure integration stack (Logic Apps, APIM, Event Grid, Service Bus) defined in Bicep. Staging mirrors production exactly. Deployed by pipeline, not by hand.

OBSERVABILITY IS NOT OPTIONAL

A system you cannot observe is a system you cannot debug or improve. Instrument before you optimize.

MyAlgoAI: API latency profiling identified the specific MongoDB query patterns responsible for 10-second responses — targeted fix, not broad caching.

DESIGN FOR FAILURE

Network failures, token expiry, and concurrent writes are not edge cases. They are operational reality.

MyAlgoAI: refresh token rotation with revocation on broker permission changes. ByBar: Service Bus for guaranteed delivery — messages survive downstream consumer failures.
